# 注册、登录反馈与聊天完成状态优化

## 行为

- 注册默认账号：服务端按北京时间日期 + 至少两位流水号生成，例如 `2026091503`，超过 99 后为 `20260915100`。独立数据库计数器使多实例并发和重启后不重复发号；跳过已有账号（包括已删除账号）。用户可修改建议账号，实际注册仍受租户账号唯一索引约束；生成建议不创建用户、不授予角色，也不保证用户手改后仍可用。注册时碰撞会明确报错。
- 新增匿名 `POST /app/account/suggest-account`，与注册入口一样设有每实例 IP 频率限制；多实例环境还应在网关限流。生成失败时允许手动输入，不猜测一个未经校验的账号。
- 注册表单账号/姓名与手机号/邮箱两列布局，密码独占一行。弹窗单一内容滚动区域跟随 visualViewport / 原生键盘高度，并滚动聚焦字段到可见范围；不禁止正常滚动。仍要求手机号、邮箱至少一项且唯一。
- 登录仅记住最近成功认证的账号，不保存密码。原生存入现有 Keychain 状态桥，网页存入本地浏览器存储；普通退出保留账号。共享设备会显示这个账号，用户可直接修改。
- 移动路由提示使用圆角浮层、明确错误色、安全区偏移。超时/网络错误不再直接显示 Axios 字符串。移动账号登录的 OAuth 错误交给页面统一提示，避免两次提示；再次登录会清掉前次提示。后台管理端样式不受这些移动路由选择器影响。
- 退出登录改为居中确认卡片，等宽“暂不退出 / 退出登录”，提醒历史记录保留，取消不会注销。

## 聊天诊断与修正

原逻辑在服务端完成动作后一次性返回正文，前端仍按每 32ms 追加少量字符模拟打字，随后等待最长 15 秒的历史读取；这两步都占用发送状态。现在正文直接更新，收到 `result` 即完成，不等待连接关闭；历史卡片在后台补齐，不锁住发送按钮。

成功正文及 result 只由控制器在事务代理返回（提交成功）后发送，避免提交失败前显示成功。保留 delta 帧兼容旧客户端。旧前端仍可能模拟打字，需要更新前端原生包才能改善体验。

流请求补上 HTTP 401 的一次令牌刷新重试（仅请求尚未通过鉴权时）。连接中断、业务错误、HTTP 500 不自动重放变更；EOF 没有 result 不算成功，会提示检查事件状态，避免重复提交。

首次变更失败的截图没有具体错误和服务端日志，不能据此确认根因。新增失败编号与错误类型日志，不记录对话、密钥、SQL 参数；成功请求记录准备/模型/业务动作阶段耗时。业务动作阶段可能包含二次模型检查，并非纯数据库耗时。当前没有修改事务原子性、自动重试动作或调低校验要求。
