# 聊天状态查询与日期筛选修复

## 原因与范围

- 只读线上日志确认 `ChatJobService.status` 将 MySQL DATETIME 返回的 `LocalDateTime` 强转为 `java.util.Date`，导致进行中的任务状态、提交接口返回 HTTP 500。
- 原前端捕获所有查询异常都显示“连接暂时中断”，将服务端异常错误归因给手机网络。
- 日期输入原来使用 `input[type=date]`，会唤起 iOS 自带的英文系统日历，无法统一 App 样式。

## 修改

- 后台在 SQL 中比较任务创建时间与超时阈值，不再依赖 JDBC 驱动的时间对象类型；未变更任务去重、权限、事务提交和恢复规则，也无需数据库迁移。
- HTTP 拦截器保留错误状态和响应信息。单次查询失败静默重试，持续服务端错误显示查询异常；仅设备明确离线时显示离线。查询恢复后清除提示，账号切换或退出等待后不再提交请求。
- 新增独立中文日期范围面板，支持今天、明天、未来 7 天、不限、跨月选择、范围高亮；确认才应用，取消保留原条件。
- 日期按北京时间计算，不受设备时区影响。窄屏内日历可滚动，取消与确认按钮保持可见。

## 验证

- 回归模拟 MySQL 的 `LocalDateTime` 返回值：旧后台代码复现与线上相同异常，修复后后台任务回归通过。
- 前端覆盖正常处理、短暂超时、HTTP 500、认证错误、跨账号隔离、真实离线、日期范围和跨年闰年边界。
- Playwright 使用本地模拟接口检查正常发送无错误提示、390 像素及 320×568 布局、取消、明天筛选和还原；未写入线上业务数据。
- 最终 41 项 Node 测试通过；`ChatJobRegression`、`ChatJobIntegrationRegression` 通过；生产前端构建完成。
- 本次修改尚未提交 Git 或生成签名 iOS 安装包。后台与网页已于 2026-09-16 发布；前端日历在内置资源的 App 中需要更新安装包。
