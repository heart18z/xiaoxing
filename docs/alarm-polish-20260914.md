# 小醒系统闹铃与验收修正

## 功能与边界

- iOS 26+ 使用 Apple AlarmKit 的固定日期闹铃，由系统呈现。需要用户单独授权，不写入苹果“时钟”的闹钟列表。旧系统、旧SDK编译的App、网页均明确提示不支持，普通提醒保留。
- 事件确认卡增加“同时设置本机系统闹铃”复选框。AI只能将用户明确要求的闹钟标为 `alarmRequested`，不能声称手机已设置成功。事件确认接口成功后，客户端获取自己的任务时间，向系统申请设置，并读回状态后才提示成功。
- 事件详情可设置、更新、取消本机闹铃。对话方式确认事件的回执也可进入事件详情设置。设置失败不撤销已创建的事件，明确分别反馈。
- 每个事件在本机只有一条闹铃；只能为当前账号接收的任务设置，好友在自己的手机授权和设置。按后端北京时间转换为固定时间，不使用首次AI评估时间，不推测模糊时间。
- 闹铃存储按本机账号隔离，账号切换/退出清理本App闹铃；晚到的授权或创建结果不会恢复已退出账号的闹铃。
- 回到前台、推送刷新、事件刷新时检查已设置闹铃，更新改期并撤销停止的任务。远端变更并非离线实时同步：其他设备改期/停止后须打开这台手机的小醒同步，离线期间保留原闹铃。已在系统设置成功的闹铃不依赖网页定时器。

## 其他修正

- 语音失败关闭识别区、显示一次提示、保留草稿，不再显示上传音频文件入口。确认/取消等大，波形由真实音量驱动；确认立即停止采音，等待转写时不再显示采音波形，不自动发送消息。
- 服务器合成中文样本诊断：当前 SiliconFlow 接口 WAV 约11158ms返回20字；MP3超过30秒超时。这是一次样本观测，并非延迟保证。没有更换或泄露服务商密钥。网页仍需上传后等待服务商；新版原生App使用Apple实时语音桥接，尚需真机验证。
- `Info.plist` 补充 `NSCameraUsageDescription`。此前缺失该权限说明是点击 Take Photo 闪退的明确风险；修复效果须重新编译后真机验证。另补充 `NSAlarmKitUsageDescription`。
- 后台参数 `token_expire_time` 查到已为4320分钟（三天），Redis未查到该参数的旧缓存，没有擅自更改参数。OAuth客户端加载使用该参数乘60作为有效期。网页令牌cookie改为随服务端JWT到期时间持久保存，不延长服务端权限；原生仍走Keychain。已有旧令牌不会自动获得新有效期，请重新登录一次；互踢、改密码等撤销仍会要求登录。未使用真实账号测试三天后过期。
- 后台留白来自新增路由外层只有最小高度而无明确高度，使下层100%高度失效。修复桌面外层高度链，移动端保持现有布局。

在拿到这次源码的 Mac 上，使用包含 iOS 26 SDK 的 Xcode（Xcode 26 或更新）。在 `code/front` 执行：

```sh
npm run ios:sync

```
